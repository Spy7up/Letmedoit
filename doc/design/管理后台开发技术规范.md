# 让我做管理后台开发技术规范

> 适用范围：`letmedoit-api/sa-admin` 与 `letmedoit-admin`。
> 目标：后续 Agent 能在不破坏 SmartAdmin 底座、小程序接口和既有业务状态机的前提下持续开发。
> 配套原型：`doc/prototype/letmedoit-admin.html`。

## 1. 技术边界

- 后端：Java 17、Spring Boot 3.5、MyBatis-Plus、MyBatis XML、Sa-Token、MySQL 8。
- 前端：Vue 3 JavaScript、Vite 5、Ant Design Vue 4、Pinia、Vue Router、ECharts 5、Less。
- 不另建后台工程，不改成 TypeScript，不引入另一套 UI 或请求框架。
- `sa-admin` 只依赖 `sa-base`，禁止 import `sa-app` 的 Entity、DAO、Service、枚举；两端只共享数据库与通用底座。
- 管理端员工使用 `t_employee + Authorization`，小程序会员使用 `t_wx_member + App-Token`，两套身份和权限不得混用。

## 2. 首版功能边界

- 运营概览：会员、任务、准时率、反馈指标；注册/任务趋势；任务状态分布；最新会员。
- 会员管理：分页筛选、会员独立详情、个人指标、帮手和任务记录。
- 帮手关系：只读分页查询。首版不强制解除关系。
- 任务管理：只读分页、任务详情、参与者、完成凭证、事件时间线。首版不修改任务状态。
- 小程序反馈：分页、详情、回复、状态流转；操作表为 `t_app_feedback`，不是框架的 `t_feedback`。
- 员工、角色、菜单、部门、字典、日志等复用现有系统模块。
- 版本发布、协议发布、会员禁用和任务干预不在首版范围内，避免未经产品确认的高风险写操作。

## 3. 后端工程规范

### 3.1 包结构

业务代码放在 `net.lab1024.sa.admin.module.business.<feature>`：

```text
controller/       参数边界、权限、当前员工 ID；不写业务逻辑
service/          业务编排、统计计算、状态校验
manager/          多步写事务（首版只读模块不需要）
dao/              MyBatis DAO
constant/         后台自己的业务枚举
domain/entity/    需要 BaseMapper 写操作时的数据库实体
domain/form/      查询和写入参数
domain/vo/        接口返回模型
```

XML 放在 `sa-admin/src/main/resources/mapper/business/<feature>/`。类名、DAO 字段名使用业务完整前缀，避免与 `sa-base` 现有 Bean 冲突。

### 3.2 接口约定

- 沿用项目动作式 URL：分页 `POST /xxx/query`，详情 `GET /xxx/detail/{id}`，写操作 `POST /xxx/action`。
- 返回 `ResponseDTO`，成功码为 `0`；分页使用 `PageParam / PageResult / SmartPageUtil`。
- 每个接口使用 `@SaCheckPermission`，禁止用 `@NoNeedLogin` 规避权限。
- Form 在边界使用 `@Valid` 和校验注解；数据库参数全部使用 `#{}` 绑定。
- Controller 获取当前员工时使用 `AdminRequestUtil`，Service 不依赖 HTTP 请求/响应类型。
- 自定义 UPDATE 显式写 `update_time`；并发更新使用 `WHERE status = 期望旧状态` 并检查影响行数。

### 3.3 SQL 与统计

- 新查询写 XML，禁止 QueryWrapper，禁止全表查出后在 Java 中筛选。
- 所有业务表显式处理 `deleted_flag`；关联任务与参与者时同时过滤两边删除标记。
- 时间范围使用 `>= startTime AND < endTime`，结束日期由调用方转换为次日零点。
- 列表筛选、聚合和排序下推 SQL；分页 XML 不手写 LIMIT。仅详情内的有限关联列表可显式 LIMIT。
- 新增表字段时同步 DDL、Entity、XML 列清单和 VO，禁止只改其中一处。
- 统计 SQL 变更后必须检查实际 WHERE、索引和返回别名；数据量增长后用 EXPLAIN 评估索引。

### 3.4 指标口径

| 指标 | 口径 |
|---|---|
| 当前会员 | `t_wx_member.deleted_flag=0` |
| 单会员好友数 | `t_helper.member_id=当前会员 AND deleted_flag=0`，双向双写不再除以 2 |
| 全站好友对 | 按 `LEAST/GREATEST(member_id, helper_member_id)` 去重 |
| 参与任务 | 参与者关联有效任务，过滤两边删除标记 |
| 完成样本 | `participant.status=2 AND complete_time IS NOT NULL` |
| 准时完成 | 完成样本中 `complete_time <= task.deadline` |
| 准时率 | `准时完成数 / 完成样本数 * 100`；零样本返回 null，前端显示 `--` |
| 逾期 | 派生条件 `task.status IN (1,2) AND deadline < NOW()`，不是持久化状态 |

## 4. 前端工程规范

### 4.1 目录与命名

```text
src/api/business/letmedoit/          真实 API，文件名 *-api.js，导出对象 *Api
src/constants/business/letmedoit/    枚举，文件名 *-const.js，并在 constants/index.js 注册
src/views/business/letmedoit/        业务页面；弹窗/抽屉放页面 components 子目录
src/components/business/letmedoit/   跨页面复用组件
```

- SFC 使用 `<script setup>`；文件 kebab-case；内部导入使用 `/@/`。
- 页面不得直接写 axios/fetch；统一使用 `/@/lib/axios` 的 `getRequest/postRequest`。
- 请求统一带 loading、异常捕获和 finally；分页读取 `result.data.list/total`。
- 使用现有 `smart-query-*`、`smart-table-*`、`smart-detail-header` 样式和 TableOperator。
- 枚举通过 `$smartEnumPlugin` 展示；权限通过 `v-privilege` 或 `$privilege`，前端权限不替代后端鉴权。
- 图表必须响应 resize，并在组件卸载时 dispose；空数据、加载和请求失败状态不得白屏。

### 4.2 动态路由与详情

普通页面不在静态路由中重复登记。菜单位于后端 `t_menu`：

- `path`：浏览器路由，例如 `/letmedoit/member`。
- `component`：相对 `src/views`，例如 `/business/letmedoit/member/member-list.vue`。
- 会员详情使用隐藏菜单 `/letmedoit/member/detail`，监听 `route.query.memberId` 变化。
- 新增菜单后配置 API 权限和角色授权，再刷新权限或重新登录。

### 4.3 视觉与文案

- 主色沿用 `#1677ff`，圆角 6px，深色侧边栏，浅色内容区，紧凑卡片和小尺寸表格。
- 页面标题、登录页、环境标题统一为「让我做管理后台」。
- 移除面向用户的 SmartAdmin 官网、公众号、演示服务、更新日志等推广内容；保留源码许可证、版权及必要框架注释。
- 不使用与业务无关的装饰图片；头像加载失败使用昵称首字符或通用图标兜底。
- 数字指标必须注明口径；零完成样本的准时率显示 `--`，不伪造 100%。

## 5. 菜单与数据库脚本

- 改初始数据必须同时提交：日期目录增量 SQL、同步全量 init、日期 README、主 SQL README 变更记录。
- 增量使用 `INSERT ... SELECT ... WHERE NOT EXISTS`，不写死新增自增 ID，不写 USE，不 DROP/TRUNCATE。
- 菜单通过稳定路径/名称查询父 ID；文件 UTF-8 + LF。
- 新增权限默认只授给明确角色；超级管理员可直接验证，普通角色需单独授权验证。

## 6. 首版接口

| 接口 | 权限 | 用途 |
|---|---|---|
| `GET /dashboard/overview` | `dashboard:query` | 总览、状态分布、最新会员 |
| `POST /dashboard/trend` | `dashboard:query` | 7/30 天注册、任务、完成趋势 |
| `POST /member/query` | `member:query` | 会员与个人指标分页 |
| `GET /member/detail/{memberId}` | `member:query` | 会员详情、帮手、任务 |
| `POST /helper/query` | `helper:query` | 帮手关系分页 |
| `POST /task/query` | `task:query` | 任务分页 |
| `GET /task/detail/{taskId}` | `task:query` | 任务、参与者、事件 |
| `POST /appFeedback/query` | `appFeedback:query` | 小程序反馈分页 |
| `GET /appFeedback/detail/{feedbackId}` | `appFeedback:query` | 反馈详情 |
| `POST /appFeedback/reply` | `appFeedback:reply` | 回复并流转状态 |

反馈状态：0 待处理、1 处理中、2 已解决、3 已关闭。允许 `0→1/2/3`、`1→2/3`、`2→3`；已关闭为终态。已解决必须填写回复。

## 7. 验证与交付

- 后端：`mvn -o -pl sa-admin -am package -DskipTests -Pdev`（依赖不足时去掉 `-o`）。
- 前端：`npm run build:prod`；开发运行 `npm run dev`，API 默认 `http://127.0.0.1:1024`。
- 后端启动：`java -jar sa-admin/target/sa-admin-dev-3.0.0.jar --server.port=1024`。
- 验证菜单、接口权限、空数据、分页、详情切换、反馈并发状态、图表 resize 和生产环境地址。
- 生产前端使用同源 `/admin-api`，由网关反向代理到 sa-admin；部署前按实际网关配置核对，不得回退到官方演示服务。

### 8.4 本地联调

```bash

java -jar sa-admin/target/sa-admin-dev-3.0.0.jar --server.port=1024
```

### 8.5 已知限制（下一版再做）

- 全部为只读报表：不支持禁用会员、解除帮手关系、修改任务状态。这些是高风险写操作，需产品单独确认。
- 反馈只保留最后一次处理记录，没有处理历史表。
- 报表无导出；概览趋势最多 90 天（`DashboardTrendQueryForm` 限制）。
- 会员详情任务列表上限 20 条、帮手列表上限 50 条，都是详情内的有限关联，不再分页。
- 未做数据权限（按部门/员工隔离），所有后台账号看到同一份数据。
