# 版本管理（sa-app）

> 目标：**小程序里所有版本文字只有一个来源** —— `GET /api/version/current`。
> 代码里不再出现 `v1.1.0` 这类写死的串，改版本号只需要后台发一条记录。
> 表：`t_app_version` · 建表脚本：`docs/sql/init/letmedoit_init.sql`（全量）/ `docs/sql/updates/2026-10-27/02_version.sql`（增量）· 后台界面本期不做。

---

## 1. 为什么单独建表

以前版本号写在 `pages/mine/index/index.js` 的 `data.version` 里。问题是：

| 痛点 | 现在 |
|---|---|
| 改一个数字要重新提审、重新发版 | 后台改记录，小程序下次打开就是新版本 |
| 「关于」弹窗里的版本和代码里的对不上 | 同一个接口字段，永远一致 |
| 想写「这次更新了什么」只能写死在代码里 | `release_note` 后台可填，弹窗直接展示 |
| 历史版本查不到（几时发过什么） | 一行一个版本，保留历史 |

## 2. 表 `t_app_version`

```sql
version_id        主键
app_type          端类型 miniapp（预留 h5 / app）
version           版本号 1.1.0（不带 v，便于比较）
version_label     展示串 v1.1.0（空则服务端拼 v + version）
release_note      更新说明，展示在「关于」弹窗
release_time      发布时间
min_base_lib      最低基础库版本（预留，本期不参与逻辑）
force_update_flag 是否强制更新（预留，本期前端不读）
current_flag      是否当前对外版本；同一端只应有一行为 1
deleted_flag      逻辑删除
create_time / update_time
```

唯一与索引：

| 名称 | 作用 |
|---|---|
| `uk_type_version (app_type, version)` | 同一端同一版本不能重复（发版排重） |
| `idx_type_current (app_type, current_flag)` | 取当前版本走索引，一行命中 |

**「当前版本」不用另一张表、也不用配置项**：就靠 `current_flag`。
发版动作 = 把目标行置 1、同端其它行置 0（一个事务），查询侧永远简单。

## 3. 接口

| 方法 | 路径 | 登录 | 返回 |
|---|---|---|---|
| GET | `/api/version/current` | **免登录** | `AppVersionVO` |

```json
{
  "appType": "miniapp",
  "version": "1.1.0",
  "versionLabel": "v1.1.0",
  "releaseNote": "任务委托与提醒：多人任务、帮手、站内通知",
  "releaseTime": "2026-10-26 00:00:00",
  "minBaseLib": null,
  "forceUpdateFlag": false
}
```

免登录的理由：版本号不属于用户数据，登录页也可能要展示；白名单在 `AppMvcConfig.VERSION_PUBLIC_PATHS`。

**没配置版本时**（漏跑 SQL / 后台还没发过版）返回 `version` 与 `versionLabel` 都是空串、`code` 仍为 0，
日志打 `版本未配置…`。这样前端只是「不显示版本号」，不会因为一条数据缺失打不开页面。

## 4. 小程序侧约定

```
services/version.js#current({ refresh })  →  两级缓存
  ├─ 内存：一次会话只请求一次
  └─ 本地存储 lmd_app_version：接口挂了用上次的，别让「我的」页空白
```

**铁律：页面不许再出现版本字面量。**

| 位置 | 取法 |
|---|---|
| 「我的」页页脚 | `{{version}}`，为空时不显示 |
| 「我的 → 关于让我做」右侧 | `{{version}}`，为空时隐藏 |
| 关于弹窗标题 | `让我做` + version（有才拼） |
| 关于弹窗正文 | `versionNote` + 固定 slogan |
| 协议阅读页的「版本 x.y.z」 | 走 `t_app_agreement`，与本表无关（协议版本 ≠ 小程序版本） |

> 协议版本和小程序版本是两件事：前者变了要重新征得同意，后者只是展示。
> 不要为了「统一」把两者合并，否则每次发版都会逼用户重新同意协议。

## 5. 后台接入设计（这期不做）

### 5.1 模块位置

```
sa-admin/src/main/java/net/lab1024/sa/admin/module/business/version/
├── constant/VersionPlatformEnum.java
├── controller/VersionController.java
├── service/VersionService.java
├── dao/VersionDao.java
├── domain/{entity,form,vo}/
sa-admin/src/main/resources/mapper/business/version/VersionMapper.xml
```

> sa-admin 不依赖 sa-app，但两边共用 `t_app_version`。类名在各自模块里独立，不要跨模块 import。

### 5.2 接口与权限码

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| POST | `/version/query` | `version:query` | 分页列表，按端 + 发布时间倒序 |
| POST | `/version/add` | `version:add` | 新增版本（默认不发布） |
| POST | `/version/update` | `version:update` | 改说明 / 展示串（已发布的也能改文案） |
| POST | `/version/publish` | `version:publish` | **发布为当前版本** |
| POST | `/version/delete/{id}` | `version:delete` | 逻辑删除（当前版本不允许删） |

### 5.3 发布动作（唯一有并发风险的地方）

```java
@Transactional(rollbackFor = Exception.class)
public void publish(Long versionId) {
    AppVersionEntity target = dao.selectById(versionId);   // 校验存在、未删除
    // 1) 同端全部下线
    dao.clearCurrent(target.getAppType(), now);
    // 2) 目标上线
    dao.markCurrent(versionId, now);
}
```

`clearCurrent` 一律带 `app_type` 条件，避免把别的端（将来 H5）也下掉。
不要用「把 current_flag 当唯一索引」的方案 —— 中间态会插入失败。用事务内两步更新最简单。

### 5.4 列表查询参数（`VersionQueryForm extends PageParam`）

```java
private String appType;    // 端，空为全部
private String version;    // 版本号精确匹配
private Boolean currentFlag;
```

排序：`current_flag DESC, release_time DESC`（当前版本永远第一行，不用翻页找）。

### 5.5 缓存

本期不加缓存：一条主键/索引查询，成本可忽略，省掉「后台改了但缓存没清」的经典事故。
如果将来 QPS 上来要加，**发布动作里必须一并清缓存**（`@CacheEvict` 或删 Redis key）。

## 6. 发版流程（照着走）

1. 改代码 → 提审 → 微信审核通过并发布；
2. 后台「版本管理」新增一条：版本号 = 小程序里的实际版本，写清 `release_note`；
3. 点「发布」；
4. 验证：`curl https://你的域名/api/version/current` 返回新版本；
5. 小程序「我的」下拉刷新，页脚与关于弹窗应同步变化。

> 顺序别反：**先发小程序包，再发布版本记录**。反了会出现「小程序还是旧版，界面却显示新版本号」。

## 7. 预留字段怎么用（将来做强制更新）

| 字段 | 将来逻辑 |
|---|---|
| `min_base_lib` | 小程序启动时用 `wx.getAppBaseInfo()` 取基础库版本，低于它提示「请升级微信」 |
| `force_update_flag` | 配合微信 `updateManager`：发现新版本时强制 `applyUpdate`，不给「稍后」 |

这两个字段本期只落库、接口也返回，但前端不读取 —— 提前把列加上，避免以后改表。
